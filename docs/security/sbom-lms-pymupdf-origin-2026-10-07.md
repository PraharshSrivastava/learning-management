## Meaning for Priority 1

The published wheel itself contains the same build metadata seen in the candidate: PyMuPDF 1.28.0, embedded MuPDF SONAME 29.0, and build commit `e9cdfc9e7fe3260efcc9d28713903f075ab05bce`. The previously captured runtime engine version is MuPDF 1.29.0. The published source distribution's setup declares MuPDF 1.28.0. Thus this discrepancy is present in the published artifact; no local wheel-payload difference was found.

Follow-up [source trace](sbom-lms-pymupdf-source-trace-2026-10-07.md): the recorded PyMuPDF commit is public in the current repository; the earlier lookup used the old location. Its setup matches the verified sdist. A public MuPDF development revision matches 84 bundled headers, including its 1.29.0 version header. Exact compiled engine identity remains open.

Matching the published wheel does not establish its complete compiled dependencies or absence of stripped cJSON/librsvg/libsndfile copies. Absence of a PyPI attestation is not proof of malicious code. The six inherited High coverage assessments remain open, and the 40 Medium backlog is unchanged.

Next required evidence is a source/dependency/build record matching this exact wheel and embedded engine. If that cannot be established, prepare a replacement artifact from an independently reviewable, supported source revision after checking its advisories. Do not downgrade automatically to make version numbers match. Full native/browser provenance and real LMS validation remain necessary.

## Reproduction and scope

`scripts/security/pymupdf_installed_inventory.py` runs in an offline disposable candidate container and hashes installed distribution files without executing the PDF engine. `scripts/security/verify_pymupdf_wheel.py` checks the downloaded archive and all hashed payload identities, plus the installer console wrapper. Negative controls reject changed native hashes, unexpected native files, a wrong archive digest and an altered wrapper. Generated bytecode contents were not independently audited as source builds; the comparison is explicitly about wheel payload identity.

The first comparison left the installer-generated console wrapper unclassified. It was independently read, checked against its declared entry point and original captured hash, and then classified. No payload mismatch was found or concealed; the pre-wrapper comparison is preserved.

No dependency/image change, deployment, restart, commit, push, PostgreSQL operation or advisory suppression occurred. This read-only artifact check does not require repeating document/media tests against the unchanged candidate.
